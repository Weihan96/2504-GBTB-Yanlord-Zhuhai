# HVAC 约束式路线编制标准

## 产品形态

- 用户任务：在 Blender 三维场景中移动已确认的空调机位、添加或移动转弯点，并重建可见路线；不手工维护第二套正式几何。
- 工作模式：创建/编辑路线骨架 → 三维复核 → 机械检查 → 显式编译 IFC 候选 → 人审后写入正式 IFC。
- 最佳操作面：Blender 视口负责同时显示空调、洞口、弯点、墙梁和吊顶；RCP1 HVAC 面板只放“重建预览、添加弯点、检查、编译候选”操作。
- 必须分开：路线编辑预览与正式 IFC 写入；旧 `.blend`/DWG 参考与装修后设计；设备包围盒中心与真实厂家端口。
- 不再采用：一台设备只能配一个洞口的一对一模型、按最近距离自动认定连接、打开或保存 `.blend` 作为 IFC 同步副本、依赖 Blender depsgraph 自动写 IFC。

## 标准数据边界

1. 正式 IFC 保存已批准的设备、洞口、最终管段/风管、弯头/三通、端口、系统和连接关系。
2. `pipeline/decisions/rcp1-hvac-route-register.csv` 保存路线身份、服务房间、端点角色、依据、置信度和审核状态。
3. `pipeline/decisions/rcp1-hvac-route-waypoints.csv` 保存有序锚点。一个洞口可被多条路线引用；一条路线可依次经过多个洞口或人工弯点。
4. IFC-backed 锚点只保存 GlobalId，世界坐标每次从当前 IFC 重算。人工弯点才保存明确的 XYZ，且必须记录依据和审核状态。
5. `.blend` 只作为派生审核缓存，保存临时视图、控件或节点状态；所有预览必须能从 IFC 和两张 CSV 重新生成。审核缓存放在 gitignored 的 `build/`，不得反向覆盖 IFC。Bonsai 官方明确把 IFC 作为 BIM 真源，并警告 `.blend` 不是 IFC 模型的可靠保存/加载格式。
6. 旧 `2504_lowpoly.blend` 是拆改后近似底稿，交付 DWG 是开发商设备/系统/预留洞参考；两者不得覆盖当前 IFC，也不得被直接复制为装修后施工路线。

## 生成职责

- Python 约束脚本：解析 IFC/CSV，解析共享锚点与多段路径，生成确定性的路线骨架、检查报告和候选 IFC。
- Geometry Nodes：仅把路线曲线转为可视实体，负责圆角、截面和预览材质；不创建 IFC 端口、系统或关系。
- 最终 IFC 编译器：按介质创建明确的 `IfcDuctSegment`/`IfcPipeSegment` 与 `IfcDuctFitting`/`IfcPipeFitting`，并以嵌套的 `IfcDistributionPort` 和端口连接表达拓扑。当前 IFC4 中不得把无形端口或连接语义伪装成普通网格。
- 单一 IFC 写入者：移动设备或弯点时可自动更新 Blender 预览，但绝不自动写 IFC；“导出路线候选”只写入 gitignored 的 `build/` 证据，只有显式“编译 IFC 候选”命令才可生成候选 IFC。

## 路线几何规则

- 设备端锚点不得再使用设备包围盒中心。当前 A02/A03 预览采用设备局部 `+X` 端面的中心作为厂家接管侧候选；该方向同时由现有详细接管网格和日立 P02010Q 接管侧示意支持，但仍不是逐个冷媒/冷凝水端口的最终坐标。
- 设备端先沿局部 `+X` 的世界主轴退出 `150 mm`，再按“垂直接管轴 → 平行接管轴 → Z”连接首个固定锚点；后续锚点间按 `X → Y → Z` 生成。所有未圆角控制段必须只改变一个世界坐标轴。
- Geometry Nodes 只在可视预览中把折角圆整；当前 `120 mm` 圆角半径和 `15 mm` 预览半径不是风管或冷媒管的施工尺寸。最终半径、截面和管径必须来自厂家及施工深化输入。
- 导出候选必须同时保留原 IFC 包围盒中心、设备服务端世界坐标、局部服务端坐标、世界主轴和全部正交控制点。审计以可传入的 `--tolerance-mm` 验证固定锚点、单轴分段、锚点顺序和圆角节点存在。

## 厂家资料边界

- 日立 P02010Q 安装说明覆盖 `RPIZ-22FSLN5QD(/P)` 与 `RPIZ-22FSLN5QDF(/P)`；PDF 第 5 页给出冷媒液管/气管和排水连接侧，第 3 页给出机体及吊装尺寸。A02/A03 的 IFC 类型为 `RPIZ-22FSLN5QDF/P 700×447×192`，型号文本与该资料匹配。
- P02010Q 中 18–50 容量段的气管为 `φ12.7 mm`、液管为 `φ6.35 mm`；排水连接按说明书为外径 `32 mm` PVC，排水坡度范围 `1/25–1/100`。这些数值只进入厂家证据表，尚未授权生成当前两条综合服务骨架的独立管段。
- `RPIZ-71FSLN5Q/P` 的 IFC 型号文本缺少上述资料中的 `D`，在获得完全匹配的厂家型号资料前保持待核对，不用相近型号替代。
- 项目证据登记见 `pipeline/decisions/rcp1-hvac-equipment-interface-evidence.csv`；厂家 PDF 下载件和渲染页只保存在 gitignored 的 `tmp/pdfs/`。

## 当前已确认约束

- A02 与 A06 均服务 R07 餐厅。
- A02 的既有服务路径顺序为 `A02→H03`。
- A03 的既有服务路径顺序为 `A03→H04→H02`。
- H07 是冷凝水排放接口位置。
- H01 是室外机接口位置。
- H01/H07 当前 IFC 实体仍是 `IfcOpeningElement`。上述确认描述的是接口位置，不授权把洞口直接重分类为设备或端口。
- A02/A03 的接管侧候选采用设备局部 `+X`。A03 在世界坐标中旋转 180°，因此其路线先向世界 `-X` 退出，位于用户指出的设备另一端。

## 验收合同

- 能力：移动设备或弯点后，所有受影响路线预览自动更新，也可手动重建；允许共用洞口和多段路径，并可把当前状态导出为只读候选证据。
- 位置：路线控件属于 Blender 的 RCP1 HVAC 面板；正式写入仍由流水线命令控制。
- 禁止位置：正式连接语义不得只存在于 Geometry Nodes、`.blend` 自定义属性或屏幕标记中。
- 工作流：审图时空调、洞口、路线、墙梁与吊顶保持真深度同时可见；拆除墙只在专用半透明参考层显示。
- 状态：重建预览不改变 IFC 哈希；编译候选不覆盖正式 IFC；人审批准后才执行正式写入并 reload/rebuild。
- 证据：每次输出路线/锚点清单、源文件哈希、几何差分、连接闭合、碰撞/净距、坡度和截图；自动推断均含依据、置信度和人审标记。
- 审核缓存：当前可打开 `build/rcp1/rcp1-hvac-authoring-review.blend` 检查设备端、正交路径和圆角；该文件可删除并从正式 IFC、路线表和脚本重建。

## 当前停止条件

在厂家送回风口、冷媒液/气管口及冷凝水口的真实坐标与朝向，以及截面、保温、弯曲半径、坡度、吊架和检修净距确认前，只允许生成约束骨架和可视预览，不得生成施工发布几何。
